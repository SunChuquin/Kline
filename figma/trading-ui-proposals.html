Kline 交易功能 · UI 布局方案原型

两块需求：① 旧悬浮按钮点开的快捷面板增加快捷交易；② 模拟 Tab 改造为多账户、完整交易与完整历史。所有画面按真机形态绘制（iPad 横屏 1024×768、涨红跌绿、贴底面板圆角 16、SF 字体），画面内按钮可点。

样机尺寸 1024×768 面板样式对齐 FloatingAccessoryPanel / 指标选择面板 示例数据，非真实行情

落地说明（给开发的备注）

1 · 下单表单做成一个共用组件

新增 TradeTicketView，三种形态复用同一套内核：快捷面板内嵌紧凑态（方案 A）、模拟页全屏 fullScreenCover、详情页工具栏将来也可挂同一入口。方向 / 报价类型 / 价格 / 数量 / 仓位 / 费用预览全部参数化，避免三处各写一遍。

2 · 面板高度与上下文

FloatingAccessoryPanel 现固定 0.5 高度且内容为空。两种上下文建议 heightFraction ≈ 0.67（闪电条约 0.35，均受 660 上限保护）；面板通过环境拿到当前 MetaItem（详情页有值、列表页为 nil 走选标的态）。旧按钮显示范围（selectedTab == 1 || 2）无需改动。

3 · 多账户数据模型（6 个实体）

SimAccount（账户 / 初始资金 / 规则）、SimPosition（持仓 / 可用 / 成本）、SimOrder（委托 / 状态机）、SimFill（成交）、LedgerEntry（资金流水）、ActionLog（操作日志）。一个 SimStore 统一持久化（SwiftData 或 JSON），账户之间完全隔离，「全部账户」为聚合视图。

4 · 「完整历史」的口径

操作日志是全量事件流（委托、成交回报、撤单、改价、资金出入、账户变更、提醒触发，只追加不改写）；成交、资金流水是它的两个业务视图。日志支持按日期区间 / 类型 / 标的 / 账户筛选与 CSV 导出，分页加载——这就是「查看完整历史操作」的落点。

5 · 交易规则集中在交易设置

T+1 可用股数、100 股整数倍、涨跌停与最小报价档位校验、佣金万 2.5 最低 5 元、卖出印花税千一、盘后委托转「待报」下一交易时段申报——规则全部进 SimTradingRules，下单组件只做展示与校验提示，多账户可各自挂规则。

6 · 代码落点

新增 Kline/Simulation/：SimStore.swift、模型文件、SimulationView.swift（按方案 A 重建：侧栏 + 工作区）、TradeTicketView.swift、各表格 Cell；FloatingAccessoryPanel 内填充快捷交易态。行情取数复用 MarketRowCache / 详情页已加载的收盘价，盘后用最后收盘价做模拟成交。
