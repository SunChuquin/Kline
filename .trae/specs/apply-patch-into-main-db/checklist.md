# Checklist

> 勾选依据：**代码级核对** 或 **本次真跑输出**（命令 stdout / 设备返回可查）。

## 门槛：先量准预算（Task 0）

- [ ] 只读原型**没有写任何库、没有动设备**（真库 sha256/mtime 未变）
- [ ] A（分类 + 解析纯追加尾部）实测秒数已记录
- [ ] B（195 个改写文件整文件解析 + 与基线库逐行比对）实测秒数已记录
- [ ] C（出包到临时文件）实测秒数已记录
- [ ] 补丁实际行数与体积已记录（对照 77.1MB / 860,897 行上界）
- [ ] 给出 A+B+C+D+E 的**总预算**（D/E 用实测锚点外推），并明确是否 < 60s
- [ ] 若合计 ≥ 60s：**已停下回报**，未进入 Task 1~3

## 分类（Task 1）

- [ ] `changed_files` 返回新增 `kind`（`append`/`rewrite`/`new`），既有键不变
- [ ] 三处采样（头 4KB / `旧长度/2` 处 4KB / 旧尾 4KB）与旧文件同位置比对；三处全一致 ⇒ `append`
- [ ] 拿不准（读失败、长度异常）一律按 `rewrite`
- [ ] 每个文件只开 2 次句柄（旧、新各一次），多次 seek 在同一句柄内完成
- [ ] 真实目录实测 `append≈3442 / rewrite≈195 / new=4`，耗时与 18.6s 同量级（不显著变差）

## txt 直出差分（Task 2）

- [ ] 全程**不重建 `tdx.db`**；旧值真相源是基线库
- [ ] `append` 文件只解析 `旧长度` 之后的尾部行，全部计 `new_only`，**未做行级比对**
- [ ] `rewrite` 文件与基线库逐行比对，**只产出真正不同的行**（值相同的一行都不进包）
- [ ] `new` 文件全部行按新增
- [ ] 补丁表结构与字段顺序**逐字沿用** `build_bucket_file`（`bkt_meta`/`bkt_daily`/`bkt_weekly`/`bkt_monthly`）
- [ ] 周/月线口径与既有实现一致（未另发明一套聚合）
- [ ] **正确性硬门槛**：产物与「重建库后跑 `diff_live_patch --no-prune`」**逐行一致**（差异行数逐周期相同、内容相同）
- [ ] 全流程**没有 1.4GB 级全文件读**（不存在 sha256 全库校验路径）

## 设备侧按行落主库（Task 3）

- [ ] 新增 `POST /sync/apply-patch` 路由，邻接既有 `/sync/*` 风格
- [ ] 合并不在 HTTP 线程同步执行，完成后回主线程响应
- [ ] 写入是**一条集合式 SQL**（`INSERT OR REPLACE ... SELECT ... FROM bkt.bkt_* JOIN main.meta ON m.file=b.file`），**不在 Swift 里逐行 bind**
- [ ] 映射键是 `file`（未使用 `code`）
- [ ] 单事务 + 失败 ROLLBACK，主库保持原样；响应含失败原因
- [ ] 完成后更新 `meta.last_date` 并热刷新（`dataVersion` 自增）
- [ ] **不替换整个 `tdx.db`**、**不需要重启 App**、**不经过增量库**
- [ ] 响应含日/周/月行数、覆盖标的数、`latestDate`

## 端到端实测（Task 4）

- [ ] 四步串起来跑通，各阶段耗时有原始输出留档
- [ ] **端到端总耗时 < 60s**
- [ ] 设备主库 `latest_date == 20260922`
- [ ] 抽查标的（含 1 只扩展指数）**交易日连续、无缺口**
- [ ] 「只更新差异」得到核对：写入行数 ≈ 补丁行数，**远小于全库 1400 万行**
- [ ] 补丁体积与量级相符（不是全库级几百 MB）
- [ ] 实测数字写入 `tasks.md` 与 `.trae/documents/live-sync/` 对应篇

## 本地基线同步（Task 5）

- [ ] 提供把同一补丁应用到本地基线的一次性命令
- [ ] 文档写明该步骤**不计入 60s 预算**，但不做会导致下一轮重复计算已同步的差异
- [ ] 应用后本地基线与设备主库内容一致
