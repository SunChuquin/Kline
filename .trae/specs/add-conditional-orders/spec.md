# 条件单 Spec

## Why

模拟交易目前只有「限价 / 市价」两种即时委托（`SimOrder`），下单即校验即成交，无法预先设定触发条件、由系统自动盯盘下单。而市面主流券商 APP 已把条件单做成标配（价格条件、止盈止损、回落卖出、网格交易等），本项目缺这一层，模拟交易复刻不了「提前布局、自动执行」的真实场景，也无法验证纪律化交易策略。

## What Changes

* 新增条件单领域模型与持久化（`sim.json` schemaVersion 1 → 2）

* 新增条件单评估纯函数层与触发引擎 `SimCondEngine`（行情刷新 + 手动检查两个触发时机）

* 新增条件单**独立二级页**：管理页 `SimCondListView` + 编辑器 `SimCondEditorView`

* 新增三处条件单入口：模拟页三个布局的工具栏、全屏下单页、持仓表行内按钮

* 新增操作日志模块 `ActionModule.condition`，新增 `SimOrder.originCondID` 回链

**BREAKING**：`sim.json` 根结构新增 `conditionalOrders` 字段。读档逐项兜底（字段缺失即空数组），旧档案继续可读，用户无需迁移；写档后旧版本 App 读新档会丢弃条件单，但不影响其余五类数据。

## 市面条件单梳理（研究结论）

按「触发依据」归类，A 股券商 / 期货 APP 的条件单矩阵如下：

| 类别          | 触发依据                    | 触发后     | 常见形态与要点                                   |
| ----------- | ----------------------- | ------- | ----------------------------------------- |
| 价格条件        | 现价 ≥ 或 ≤ 触发价            | 单次      | 上破买入 / 下破卖出，最普及的底座                        |
| 涨跌幅条件       | 当日涨跌幅达到 ±X%             | 单次      | 以此前收盘为基准                                  |
| 时间条件        | 到达指定交易日时刻               | 单次      | 定时买卖；定投是同类的多触发变体                          |
| 止盈止损        | 现价触及止盈价 / 止损价           | 单次      | 双边为 OCO：先触发为准，另一条自动失效；可按价格 / 百分比 / 差价三种基准 |
| 回落卖出 / 反弹买入 | 从突破后的极值回撤 N% 或差价        | 单次      | 即追踪止损；常带「保底价触发」高级开关                       |
| 均线条件        | 上穿 / 下破 MA5/10/20/30/60 | 单次      | 盘中按「最新价 + 前 N 日均价」折算                      |
| 形态条件        | MACD 金叉 / 死叉 / 背离       | 单次      | 需 1/5/15/30/60 分钟级 K 线                    |
| 涨停买入 / 开板卖出 | 封板状态、买一封单量萎缩            | 单次      | 开板立即卖 / 开板回落卖 / 封单萎缩触达，依赖盘口数据             |
| 网格交易        | 价格在区间内每走一个网格步长          | **多触发** | 到价触发型 / 成交驱动型；含价格区间、倍数委托、持仓区间、监控时段        |
| 分批建仓 / 分批卖出 | 价格阶梯逐档达到                | **多触发** | 把大单拆成 2\~5 笔按价差分批                         |
| 联动买卖        | 联动品种的价格                 | 单次      | 跨品种套利场景                                   |
| 低频自动化       | 时间（打新 / 定投 / 逆回购）       | 多触发     | 与行情无关，属资金自动化                              |

所有条件单共享的通用属性：

* 标的、委托方向、触发条件、**触发后的委托指令**（市价 / 限价 / 触发价 ± N 档）、数量（股数 / 金额 / 仓位比例）

* 有效期：当日 / 指定日期 / 长期

* 状态：监控中 / 已触发 / 已完成 / 已失效 / 已撤销 / 触发后被拒

* 触发记录与消息推送

## 本次范围

**纳入（8 类，进阶版）**：价格条件、止盈止损（OCO）、回落卖出 / 反弹买入（追踪止损）、时间条件、涨跌幅条件、均线条件、网格交易、分批建仓 / 分批卖出。

**不纳入**（连同原因）：

* MACD 形态条件：需要分钟级 K 线，本项目行情库只有日 / 周 / 月级

* 涨停买入 / 开板卖出：需要封单量与盘口数据，本地库没有

* 联动买卖：需要多标的实时对齐，与本项目「单一最新价」模型不匹配

* 预约打新 / 定投 / 逆回购：与行情触发无关，属资金自动化，不在本次

* 算法单（TWAP / 冰山 / 篮子）：机构端能力，不是条件单

## 关键约束与取舍

**约束**：本项目的「最新价」是本地日线库最后一根 K 线的 `close`（见 `MarketRow.compute(.latestPrice)`），**没有盘中 tick 推送**。因此触发只能发生在「有行情快照可取」的时刻。

**已确认的取舍**：

1. **触发时机 = 行情刷新 + 手动检查**。不引入定时轮询，不引入 K 线推进。
2. **极值追踪按评估点采样**。真实券商的「回落卖出」逐 tick 更新历史最高价；本项目只能在每次评估时用当时的最新价更新极值，两次评估之间的价格路径不可见。这一点必须在 UI 上明示（见 R7 底部提示条），避免用户误以为等价于券商实时盯盘。
3. **交易时段不额外限制触发判定**。触发判定只看条件是否成立；是否真正成交仍走既有 `SimTradingRules.isTradingSession`——非交易时段触发的委托会落为「待报」，与手动下单行为一致。
4. **触发后下单失败不静默重试**。单次触发类型失败即置「已拒绝」并留因，避免无限重试；多触发类型（网格 / 分批）失败记因并继续监控。
5. **不新增行情订阅机制**。评估只读 `MarketRowCache` 已有能力（`numberFor`），不新增取数路径。
6. **一次结算的落盘次数为 N+1**（N = 本轮触发笔数）。引擎自身在整轮结算末尾只写盘一次，但触发路径必须复用 `SimStore.submit`（见「触发后的委托下发」要求：不新增旁路下单逻辑），而 `submit` 内部会自行落盘一次。两条要求存在张力，取舍是**优先保证下单路径唯一**，接受每触发一笔多一次写盘。本轮不触发时仍只有 0 次额外写盘。
7. **均线条件按「昨收 vs 最新价」判定**，而非「上一评估点最新价」。日线级数据下 `prevClose` = 昨日收盘、`last` = 最新收盘，bar 对 bar 判定既符合日线穿越的标准语义，又是幂等的（同一天内反复评估结果一致），天然避免持续满足即反复触发。`SimCondRuntime.lastPrice` 仅作记录用途，不参与判定。
8. **持仓表行内的「条件单」按钮沿用 22pt 高的共享组件**。该按钮与同行「买 / 卖」保持同一规格，加高会波及布局 C 的在途委托行；命中区未达 44pt 属已知偏差，靠行内留白补偿。

## ADDED Requirements

### Requirement: 条件单模型与持久化

系统 SHALL 定义可持久化的条件单实体，覆盖 8 种类型、触发条件参数、触发后委托指令、有效期与状态，并与既有六类模拟交易数据一同落盘。

模型 SHALL 包含：

* `SimCondKind`：`price` / `stopLoss` / `trailing` / `time` / `changePct` / `maCross` / `grid` / `batch`

* `SimCondStatus`：`monitoring`（监控中）/ `triggered`（已触发）/ `completed`（已完成）/ `expired`（已失效）/ `cancelled`（已撤销）/ `rejected`（触发后被拒）

* `SimCondValidity`：`day`（当日）/ `untilDate`（指定日期）/ `longTerm`（长期）

* `SimCondDirective`：`direction`、`priceType`（market / limit）、`offsetTicks`（触发价 ± N 档）、`qty`、仓位比例

* `SimCondParams`：各类型参数的**扁平可选字段**集合（避免带载荷枚举导致的 Codable 复杂度与读档脆弱性）

* `SimCondRuntime`：`extreme`（追踪极值）、`gridLevel`（网格当前档位）、`batchDone`（分批已完成笔数）、`lastEvaluatedAt`、`lastMessage`

* `SimCondOrder`：上述字段 + `id` / `accountID` / `metaID` / `code` / `name` / `kind` / `repeatable` / `triggeredCount` / `createdAt` / `updatedAt` / `triggeredAt`

`sim.json` 根结构 SHALL 新增 `conditionalOrders`，`schemaVersion` 升级为 2，且解码时逐项兜底。

#### Scenario: 旧档案升级后无损读取

* **WHEN** 磁盘上是 schemaVersion 1 的 `sim.json`（无 `conditionalOrders` 字段）

* **THEN** 六类既有数据全部正常读出，`conditionalOrders` 为空数组，无报错、无数据丢失

#### Scenario: 条件单跨启动保留

* **WHEN** 用户创建条件单后杀掉 App 并重启

* **THEN** 条件单仍在「监控中」分段可见，触发条件参数、委托指令、有效期、运行时进度与关闭前一致

### Requirement: 条件单评估（纯函数层）

系统 SHALL 把「是否触发」的判定实现为无副作用的纯函数，输入为条件单 + 行情快照，输出为判定结果，不写任何数据。

* `SimCondSnapshot` SHALL 只承载评估所需字段：`last`、`prevClose`、`high`、`low`、`changePct`、`ma`（按需的某个周期均线值）

- 判定结果 SHALL 区分四态：`fire`（触发，携带本次下单数量与触发价）、`hold`（继续监控，可能携带新的运行时进度）、`complete`（正常走完：多触发类型档位 / 批次走完，或价格越出网格区间）、`abort`（异常失效，携带原因）

* `SimCondRule` SHALL 提供 `validateCreate(...)` 校验草稿，返回可直接展示的中文拒绝文案，复用 `SimOrderRejection` 风格的枚举

#### Scenario: 价格条件按方向判定

* **WHEN** 条件单为「现价 ≥ 1420.00 触发」，快照最新价为 1425.00

* **THEN** 判定为 `fire`

* **WHEN** 同一条件单快照最新价为 1419.00

* **THEN** 判定为 `hold`

#### Scenario: 止盈止损双边先触发为准

* **WHEN** 止盈 1480.00 / 止损 1420.00 的双边条件单，某次评估快照最新价为 1418.00

* **THEN** 判定为 `fire`，取止损腿（1420.00）为触发价，且止盈腿随之失效，条件单不再可评估

#### Scenario: 行情快照缺失时不误触发

* **WHEN** 标的行情尚未就绪（`last` 或 `prevClose` 为 nil）

* **THEN** 判定为 `hold`，不触发、不写任何数据

#### Scenario: 均线条件区分上穿与下破

- **WHEN** 条件单为「上穿 MA20」，快照最新价 ≥ MA20 且昨收 < MA20
- **THEN** 判定为 `fire`

- **WHEN** 条件单为「上穿 MA20」，快照最新价 ≥ MA20 但昨收也 ≥ MA20
- **THEN** 判定为 `hold`（bar 对 bar 判定，同一天内反复评估结果一致，不会持续满足即反复触发）

### Requirement: 触发引擎与触发时机

系统 SHALL 提供统一的条件单结算入口 `SimCondEngine`，在「行情刷新」与「手动检查」两类时机下评估全部监控中的条件单。

* 引擎 SHALL 对同一次结算做互斥保护（评估中不重入）与短窗口合并（高频 `MarketRowCache.rows` 变化不得引发结算风暴）

* 触发源 SHALL 至少包含：`SimStore.prepareQuotes()` 结束时、数据库就绪时、`MarketRowCache` 行数据就绪时、条件单页「立即检查」按钮

* 结算 SHALL 最终只落盘一次（批量写盘），且所有写入沿用 `SimStore` 的「值未变不写」守卫

#### Scenario: 行情就绪后自动结算

* **WHEN** 数据库加载完成、持仓与条件单标的的行情 bars 就绪

* **THEN** 引擎自动结算一次，满足条件的条件单进入「已触发」并生成委托

#### Scenario: 手动检查反馈结果

* **WHEN** 用户在条件单页点击「立即检查」

* **THEN** 页面就地提示本次结果（如「本次检查触发 1 笔」或「本次检查无触发」），列表同步刷新

#### Scenario: 高频行情写入不引发结算风暴

* **WHEN** 多只标的的 bars 在短时间内陆续回写，触发 `MarketRowCache.rows` 连续变化

* **THEN** 引擎在合并窗口内只结算一次，不出现逐条重复结算

### Requirement: 触发后的委托下发与失败处理

条件单触发后，系统 SHALL 通过与手动下单**完全相同**的校验与写入路径生成委托，不新增旁路下单逻辑。

* 生成的委托 SHALL 记录 `originCondID` 回链到条件单

* 单次触发类型：触发并下单成功后状态置 `triggered`；下单被拒则置 `rejected` 并记录原因，不重试

* 多触发类型（网格 / 分批）：单次失败记录原因并保持 `monitoring`；达到档位上限或价格越界后置 `completed`

* 每次触发与失败 SHALL 写一条 `ActionModule.condition` 操作日志

#### Scenario: 触发后按市价成交

* **WHEN** 条件成立、处于交易时段、账户资金充足

* **THEN** 生成委托并即时成交，资金流水与持仓同步变化，条件单状态为「已触发」，操作日志出现条件单记录

#### Scenario: 触发后资金不足

* **WHEN** 条件成立但可用资金不足（或卖出时可卖数量不足）

* **THEN** 条件单置「已拒绝」，原因文案显示在列表行与详情中，账户数据不发生任何变化，且不会反复重试

#### Scenario: 非交易时段触发

* **WHEN** 条件在非交易时段成立

* **THEN** 委托落为「待报」（与手动下单一致），条件单状态为「已触发」

### Requirement: 有效期与失效

系统 SHALL 支持三种有效期，并在结算时先行判定有效性。

* 当日有效：跨自然日后置 `expired`

* 指定日期：超过该日期后置 `expired`

* 长期有效：不因时间失效

* 用户撤销 SHALL 立即置 `cancelled`，该条件单此后不再参与结算

#### Scenario: 当日有效条件单跨日失效

* **WHEN** 一张「当日有效」的条件单在当日未触发，次日 App 启动

* **THEN** 该条件单进入「已失效」分段，不再参与结算

#### Scenario: 撤销后不再触发

* **WHEN** 用户在「监控中」分段撤销一张条件单

* **THEN** 状态变「已撤销」，即便后续条件成立也不会生成委托

### Requirement: 多触发类型进度推进

网格交易与分批建仓 SHALL 支持在有效期内反复触发，并可视化推进进度。

* 网格 SHALL 支持：基准价、价格区间（上 / 下）、网格间距（百分比或差价）、每格数量、倍数委托、区间内档位数预估

* 分批 SHALL 支持：总数量、分批笔数（2\~5）、首批价格、每批价差

* 运行时 SHALL 记录已触发档位与已成交笔数，并在列表行展示「N/M 档」进度

#### Scenario: 网格逐档触发

* **WHEN** 网格设置为区间 1400\~1500、间距 1%、基准 1450，某次评估快照价落到下一档

* **THEN** 生成该档委托并推进档位，条件单保持「监控中」，列表进度前进

#### Scenario: 网格走到边界完成

- **WHEN** 网格已完成全部档位，或后续快照价越出价格区间外
- **THEN** 判定为 `complete`，条件单置「已完成」，停止参与结算（注意：这与 `abort` 不同——越界是网格策略的正常终点，不是异常失效）

### Requirement: 条件单管理页 UI

系统 SHALL 提供独立全屏管理页（`SimCondListView`），作为条件单的统一查看与操作载体。

* 导航栏：左「关闭」、中标题「条件单」、右「新建」

* 概览条：监控中 / 已触发 / 已失效 三段计数

* 分段控件：监控中 / 已触发 / 已失效（已失效含已撤销、已过期、已拒绝）

* 列表行 SHALL 同屏展示：标的名 + 代码、状态标签、类型标签、条件摘要、委托指令摘要、有效期、行内操作（撤销 / 编辑）、多触发进度

* 底部 SHALL 常驻「行情刷新与手动检查时评估，非实时盯盘」提示与「立即检查」按钮

* 空态 SHALL 给出「暂无条件单」与新建引导

#### Scenario: 三段筛选互斥

* **WHEN** 用户在分段控件上切到「已触发」

* **THEN** 列表只展示已触发的条件单，监控中与已失效的行不出现

#### Scenario: 行内撤销

* **WHEN** 用户在某张「监控中」行的操作区点「撤销」

* **THEN** 该行移出「监控中」分段，在「已失效」分段可见，状态为「已撤销」

### Requirement: 条件单编辑器 UI

系统 SHALL 提供独立全屏编辑器（`SimCondEditorView`），支持创建与编辑 8 种条件单。

* 结构自上而下：标的头卡 → 方向大分段（买入红 / 卖出绿）→ 类型 chips（8 种，横向可滑）→ 类型参数卡 → 触发后委托指令卡 → 有效性 → 预览摘要 → 提交

* 类型参数区 SHALL 随类型切换，且切换类型时保留已填的「方向 / 委托指令 / 有效性」，只重置类型参数

* 预览摘要 SHALL 用一句自然语言复述完整语义（标的 + 条件 + 指令 + 有效期）

* 校验失败原因 SHALL 就地红字展示，不弹 alert

* 卖出方向的止盈止损 SHALL 以持仓成本价为默认基准价；无持仓时 SHALL 禁止保存并说明原因

#### Scenario: 类型切换保留通用字段

* **WHEN** 用户填好「卖出 500 股、长期有效」后从「止盈止损」切到「回落卖出」

* **THEN** 方向、数量、有效性保持不变，仅类型参数区按新类型重置

#### Scenario: 创建后立刻可见

* **WHEN** 用户在编辑器中提交一张合法条件单

* **THEN** 编辑器关闭，管理页「监控中」分段立即出现该行，摘要与预览一致

#### Scenario: 非法参数被拦截

* **WHEN** 用户把网格价格区间下界填得高于上界后点提交

* **THEN** 提交按钮无效或提交后就地展示中文拒绝原因，不创建条件单、不写盘

### Requirement: 条件单入口

系统 SHALL 在三个自然位置提供条件单入口，均带入当前上下文（账户 / 标的 / 方向 / 数量）。

* 模拟页三个布局（A / B / C）的工具栏：「条件单」按钮（带监控中数量角标），打开管理页

* 全屏下单页 `TradeTicketView` 的 `full` 形态：新增「条件单」入口，把当前已填的方向 / 价格 / 数量带入编辑器

* 持仓表行内：新增「条件单」小按钮，直达卖出方向的止盈止损编辑器（基准价预填成本价）

#### Scenario: 从下单页转条件单

* **WHEN** 用户在全屏下单页填好「卖出 600519 500 股」后点「条件单」

* **THEN** 编辑器打开且方向为卖出、数量 500、标的为 600519，用户只需补触发条件即可保存

#### Scenario: 从持仓一键建止盈止损

* **WHEN** 用户在持仓表某行点「条件单」

* **THEN** 编辑器打开，类型默认为止盈止损、方向卖出、基准价为该持仓成本价、数量为可卖数量（整手）

### Requirement: 触发记录与操作日志

系统 SHALL 记录条件单的每次评估触发与失败，并在操作日志中可筛选。

* `ActionModule` SHALL 新增 `condition`（「条件单」）取值

* 日志内容 SHALL 包含标的、类型、触发结果；失败时包含拒绝原因

* 条件单详情 SHALL 至少展示：条件定义、委托指令、有效期、创建时间、触发记录（时间 + 结果）

#### Scenario: 日志模块可筛选条件单

* **WHEN** 用户在操作日志表按「条件单」筛选

* **THEN** 只展示条件单相关的触发与失败记录

#### Scenario: 触发记录可追溯

* **WHEN** 用户查看一张已触发条件单的详情

* **THEN** 能看到触发时刻、触发价、生成的委托编号，以及下单成功或失败的原因

### Requirement: 深色模式与既有 UI 规范一致

条件单全部界面 SHALL 沿用项目既有 UI 约定。

* 背景一律语义色（`Color(.systemBackground)` / `Color(.secondarySystemBackground)`），不使用 `Color.white` / `Color.black`

* 买入 `Color(.systemRed)`、卖出 `Color(.systemGreen)`

* 所有可点击元素命中区不小于 44×44pt

* iOS 15 兼容：不使用 Table / Chart / NavigationStack / `@Observable`

#### Scenario: 深色模式可读

* **WHEN** 系统切换到深色模式后打开条件单管理页与编辑器

* **THEN** 卡片、文字、分段控件、标签均正确适配，无白底黑字残留

### 8 种类型的参数区差异（编辑器同一骨架，仅此处切换）

| 类型          | 参数行                                               |
| ----------- | ------------------------------------------------- |
| 价格条件        | 触发方向（现价 ≥ / 现价 ≤）· 触发价                            |
| 止盈止损        | 基准价 · 涨跌基准（价格/百分比/差价）· 止盈 · 止损 · OCO 提示           |
| 回落卖出 / 反弹买入 | 突破价 · 回落/反弹幅度（% 或差价）· 保底价触发开关 · 保底价               |
| 时间条件        | 日期 · 时刻 · 「仅在交易日时段内提交」提示                          |
| 涨跌幅         | 阈值（+X% / −X%）· 方向                                 |
| 均线条件        | 均线周期（5/10/20/60）· 穿越方向（上穿/下破）· 右侧显示当前均线值          |
| 网格交易        | 基准价 · 价格区间（上/下）· 网格间距（% 或差价）· 每格数量 · 倍数委托 · 档位数预估 |
| 分批建仓 / 卖出   | 总数量 · 分批笔数（2\~5）· 首批价格 · 每批价差 · 笔数分布预览            |

### 交互细节

* 切换类型只重置类型参数区，方向 / 委托指令 / 有效性保持不变

* 卖出方向 + 止盈止损：基准价默认取持仓成本价；无持仓时禁用保存并提示原因

* 校验失败就地红字（位于提交按钮下方），不弹 alert——与 `TradeTicketView` 现有约定一致

* 提交成功后编辑器关闭，管理页「监控中」分段立即插入新行（无需手动刷新）

* 「立即检查」用底部 toast 反馈结果，不阻塞列表滚动
