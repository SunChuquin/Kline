# Checklist

## 清单并集（Task 1）

- [ ] `WatchlistSymbols` 以主库 `meta` 表（`id`/`file`/`code`）建字典，未把 6 位 `code` 直接当键
- [ ] 并集覆盖 6 类：自选 / 分组（含公式组 `cachedMatches`）/ 置顶 / 预警 / 条件单 / 委托
- [ ] 输出统一为 `SH#600000` 形式的 `file`，扩展指数为 `27#xxx` / `62#xxx` / `102#xxx`
- [ ] 清单为空时返回空集且不报错、不写库

## 东财取数（Task 2）

- [ ] secid 映射与 `live_db_builder.secid_for_file` 一致：`SH#`→`1.`、`SZ#`/`BJ#`→`0.`、`SH#999999`→`1.000001`
- [ ] 扩展指数从内置覆盖表取 secid；缺失的 `27#HS*` 被识别并跳过（有日志，不静默）
- [ ] 批量快照每批 ≤ 100 个 secid；OHLC 用 `f17/f15/f16/f2`，量额用 `f5/f6`
- [ ] 交易日一律由 `f124` 按北京时间（UTC+8）换算；无任何以本机日期充当交易日的分支
- [ ] 请求带 User-Agent；失败有指数退避重试；单批失败不影响其他批
- [ ] 30 只跨市场样本（含 1 只扩展指数）实测拿到当日 OHLC + 成交量 + 成交额

## 调度与触发（Task 3 / 4）

- [ ] 调度时刻为四档 11:00 / 14:30 / 15:05 / 17:30（`TdxSyncConfig` + `TdxSyncManager`）
- [ ] 非交易日不触发；前台缺失时回到前台补跑一次；同刻重复触发被去重
- [ ] 写入增量库走 `(file, date)` UPSERT，`live_meta` 能补缺失标的
- [ ] 内容确实变化才自增 `dataVersion`；重复拉取同一快照不自增、不重扫（无发布风暴）
- [ ] 触发后日志可见完整链路：并集 N 只 → 命中 M 只 → 写入当日一根 → `dataVersion` 自增 → `MarketRowCache` 重取 → `sweepConditions(.dataReload)`
- [ ] 全程无需重启 App
- [ ] 条件单 + 预警各挂一个（并集内标的），触发一次拉取后均产生对应触发记录
- [ ] 设置面板展示并集标的数、四时刻各自最近结果、批次与命中数、当日最新交易日，并区分四态
- [ ] 11:00 / 14:30 的写入在 UI 上被标注为「快照」（未完成K线）

## 导入端重建（Task 5）

- [ ] `tdx_parser.py` 提供重建模式，忽略 `last_size` 后从头全量读入并覆盖写入
- [ ] 默认增量行为保持不变
- [ ] 同一份 txt 下，重建模式对已除权标的的历史价格与 txt 逐行一致（增量模式不一致 → 证明复权改写漏读的坑已修）

## 差分包（Task 6 / 7）

- [ ] `patch_<seq>.db` 表结构与分片一致（`bkt_meta`/`bkt_daily`/`bkt_weekly`/`bkt_monthly`），可含任意多日期
- [ ] 补丁包不占用、不影响分片的 30 片滚动；清理策略独立
- [ ] manifest 含 `patches` 数组，元素带 `file`/`id`/`bytes`/`rows`/`sha256`
- [ ] 设备侧合并补丁包后 `dataVersion` 自增，且该标的历史与 PC 新库逐行一致、图表无跳空
- [ ] `diff_live_patch.py` 按 `file` 关联，未使用 `meta_id`
- [ ] 差异判定包含 `open/high/low/close/vol/amo` 任一字段变化，且包含基线中不存在的 `(file, date)`
- [ ] 基线库只读打开，跑完 sha256 与 mtime/size 均未变（有硬校验输出）
- [ ] 新旧库完全一致时不产空包，明确打印「无差异」

## 实测留档（Task 8）

- [ ] 全量推送实际秒数有原始输出留档
- [ ] 常态差分（含复权重灌）包体积与实际秒数有原始输出留档
- [ ] 设备侧合并实际毫秒数有日志留档
- [ ] spec「答疑」表中被替换为实测值的项已标注「实测」

## 硬约束回归

- [ ] 主库 `tdx.db` 表结构与「启动时打开」语义未被改动
- [ ] PC 侧脚本对 `tdx.db` / 基线库均为只读打开，无任何写入路径
- [ ] 未引入设备内常驻进程（无 root 守护）
- [ ] 东财为第三方接口，失败路径有降级与逐条日志，不阻塞 App 主流程
- [ ] 既有 `add-live-data-auto-sync` 能力（分片推送、热刷新、三通道）未被破坏
