## 四、阻塞点、风险点与需协调资源

### 阻塞点
1. **真机资源依赖**：两处真机验证（引擎部署通道 Task 4.1、内嵌引擎真机 slice 验收）都卡在用户需连接 iPad mini 4 实物设备；纯代码/模拟器侧已全部闭环，无法自行解除。

### 风险点
2. **引擎包境内分发**（§7.1 遗留）：GitHub Release 直连在国内设备不可用（下载引擎包需开代理），候选为 gitee / cnb 镜像——**尚未决策**，是「引擎部署全自动通道」在真机端到端能否跑通的环境风险。
3. **网络环境抖动**：实验 3 已踩坑——https TLS 握手在用户网络被掐；urllib 默认读系统代理必须 `ProxyHandler({})` 禁用。生产取数若下沉需继承这些防护。
4. **未提交规格文件**：`add-engine-deploy-channel/spec.md` + `checklist.md` 仍在工作树（untracked），若清理工作区有丢失风险，需尽快随 Task 5 入库。

### 需协调资源
- **用户真机**：iPad mini 4（USB，TrollStore 环境）用于引擎部署通道取证与内嵌引擎真机验收。
- **引擎包国内镜像**：gitee / cnb 镜像通道的账号与仓库授权（决策 + 落地）。
- **部署助手（Windows 侧）**：引擎分发编排的 HTTP 契约已定义，但 Windows 侧代码不在本仓库，需对侧按契约实现（本仓库仅落文档）。
