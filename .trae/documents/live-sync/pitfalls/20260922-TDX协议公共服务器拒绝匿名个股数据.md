# TDX 协议公共服务器已拒绝匿名个股数据（2026-09-22）

## 现象

- **easy_tdx 标准协议（7709）**：试了 **25 台**服务器，全部「TCP 连接与握手成功 → 取 K 线命令返回空响应体」，
  报 `TdxDecodeError: day datetime: 数据不足`。
- **MAC 协议**：`MacClient.get_stock_kline` / `get_stock_quotes` 全空（`rows: 0`）。
- **pytdx 交叉验证**（换老牌库、换内置服务器表）：8 台同样模式——
  `get_security_bars` / `get_security_quotes` / `get_security_list` 全 `None`。
- **反例**：`get_security_count` **正常返回**（沪 27472 / 深 24296）。
- `count < 100` 与 `count ≥ 100` 都空（所以「count 太小导致空」不是根因）。
- 期望的 `offline sync-all` 子命令**在 easy_tdx 里根本不存在**（误以为有）。

## 根因

**不是网络问题**（TCP 可达、握手成功、统计类命令有数据），是**服务端策略**：
统计类命令放行，个股行情类命令（K线 / 报价 / 列表）对匿名连接一律返回空。
两个彼此独立的实现（easy_tdx、pytdx）结论一致，排除了「是某个库的 bug」。

## 现在的规避方式

放弃把 TDX 协议当作日K主线，改为：

- **设备侧**：东财公开接口（`push2.eastmoney.com/api/qt/ulist.np/get`），已实测 3312/3312 命中、184 秒。
- **PC 侧兜底**：本机通达信 vipdoc 的 `.day` / 导出的前复权 txt，是**扩展行情指数（27#/62#/102#）的唯一来源**
  （本机 `ds/lday` 274/299 命中）。

**证据落盘情况（重要）**：上述失败只有**探针源码**留在磁盘上（`Kline/build_logs/_tdx_probe.py`、
`_pytdx_probe.py`、`_probe_ext*.py`），它们是 `print` 到 stdout、**没有重定向到任何日志文件**；
`build_logs/` 又整个在 `.gitignore` 里。所以**原始输出基本只存在于当时的会话中，未落盘**。
若将来要重新质疑这个结论，得重跑探针。
