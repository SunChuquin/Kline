# 换了「同规模」的库当基线，产出千万行假差异（2026-09-22）

## 现象

用 `C:\Users\sunck\home\projects\tdx_project\tdx.db` 当差分基线，跑出的差异统计是：
daily 改写 **12,317,241** 行 / 新增 1,690,944 行 / 基线独有 1,582,957 行。
两库明明是同一批数据（同为 3611 只、同日期范围 19900102~20260828），差异却几乎等于全库。

## 根因

生成器按 `file` 关联两库，而 `file → meta_id` 是**各库自己分配的**：
- 主库 `meta.id` 按导入顺序；
- 那份基线库的 `meta` 表却是**按字母序重排**（id 1..3611），而它的**数据表**用的是另一套 id（3..3637）。

**决定性判据**：按 `meta_id` 直接对齐两库时，1400 万行日线的**值差异为 0**——
说明那份库的数据表其实就是主库同一份，只有 `meta` 表是另一套排序。
于是「按 file 关联」把两份本来相同的数据错配成了几乎全库差异。

## 现在的规避方式

出包前先跑 `check_meta_consistency`：核对 `meta` 行数、悬空 `meta_id` 行数、`first_date`/`last_date` 是否与数据相符，
**任一库不自洽就立刻停住**（`exit 3`），不进差异扫描、不产包，并提示改用「设备已同步版本主库的整份拷贝」当基线。

正确基线已存档：`C:\Users\sunck\home\tdx_baseline.db`。
