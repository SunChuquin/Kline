# Beyond Compare 默认按「时间戳+尺寸」判差异，同尺寸改写会漏（必须 `criteria crc`）（2026-09-22）

## 现象

用 BC5 的文件夹比较判定「哪些 txt 变了」时，若脚本里只写 `load` + `folder-report`：
两个目录里**明明有一个文件内容不同（字节数相同、mtime 也相同）**，报告却写 `不同的文件 (0)`，完全漏掉。

实测（3637 文件 / 701MB×2，其中 24 个文件被同尺寸改写）：
- 不写 `criteria`：`不同的文件 (0)` ❌
- 加一行 `criteria crc`：`不同的文件 (24)` ✅ 零漏零多

## 根因

BC 文件夹比较的**默认比较标准是「时间戳 + 尺寸」**。内容变了但尺寸不变、且时间戳恰好相同（同秒）时，
BC 会直接判为「相同」，**根本不去读文件内容**。

而我们的场景恰恰是「同尺寸改写」——复权改写是价格等比缩放，字符数常常不变。

## 现在的规避方式

脚本里在 `load` 之后**显式声明比较标准**：

```
load "<old_dir>" "<new_dir>"
criteria crc
expand all
folder-report layout:xml options:display-mismatches output-to:"<report.xml>"
```

其他必须注意的点（都已实测）：

- **BC 是 GUI 程序**：必须带 `/silent` `/closescript`，并用 `subprocess.run([...], capture_output=True, timeout=…)`；
  否则可能弹窗并挂住。**不要**用 `shell=True`（引号会被 Windows 命令行吃掉，脚本变成无效内容而静默失败）。
- **报告格式用 `layout:xml`**：结构化、状态码是英文（`diff` / `ltonly` / `rtonly` / `ltnewer` / `rtnewer`），
  **与界面语言无关**；`layout:summary` 的分节标题是本地化中文，靠它解析很脆。
- `<filecomp>` 里 `<name>` 会在 `<lt>` 与 `<rt>` 各出现一次 → 取名字要**去重**。
- `layout:csv` 不支持（exit 106）。
- BC 找不到 / 退出码非 0 / 没生成报告 → **退回内置 `content` 模式**并写明原因，不要中断。
