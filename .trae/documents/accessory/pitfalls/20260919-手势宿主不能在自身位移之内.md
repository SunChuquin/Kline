# 手势宿主不能在它自己驱动的位移之内（2026-09-19）

## 现象

新按钮拖动「不跟手」：按钮能跟着走，但**永远追不上手指、越拖落后越多**（稳态约为手指位移的一半）。
结构几乎相同的旧按钮却完全跟手。

## 根因

`.local` 坐标空间是**手势宿主视图自己的坐标系**。若手势挂在 `.position(...)` / `.offset(...)` **之内**
（即 `gesture` 在前、`position` 在后），而那个位移量又由本次手势的 `translation` 驱动，就会形成负反馈：

```
宿主每帧已经移动了 dragDelta
value.location 是在「移动之后」的坐标系里量的
→ translation = 手指位移 − 已应用的 dragDelta
→ 稳态 d = m − d → d = m/2
```

于是按钮只走到手指的一半距离，表现为"越拖越落后"。这不是性能问题（每帧只多几次算术），是坐标系问题。

**识别特征**：手感像是"阻尼/发飘"、没有明显掉帧；而把位移量换成常量（不跟手）时一切正常。

## 现在的规避方式

把手势挂在**会移动的那个修饰符之外**：

```swift
.contentShape(Circle())
.position(shown)      // 先定位
.gesture(DragGesture(minimumDistance: 0, coordinateSpace: .local))   // 再挂手势
```

`contentShape` 仍限定命中区域，`.position` 只影响布局/放置，所以命中圈照常跟着走。

**代价**：`.local` 变成**容器坐标系**，凡是「以本控件圆心为基准」的计算（落点半径判定、`atan2` 角度）
必须由调用点传入当前中心（本模块传的是 `shown`），不能写死控件自身的半宽。
