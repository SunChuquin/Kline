# 主格永不冻结（2026-09-19）

## 现象

联动多图模式下，在**第一格/主格**上把光标往边缘推 —— **光标纹丝不动，像被冻住**；
连带「光标自动移动时隐藏两个悬浮按钮」也不会触发（因为自动滚动根本没开始）。

## 根因

手势入口第一帧就有这道闸门（`ChartGestureHandlers.swift:43`）：

```swift
if isLinkedFrozenView { return }
```

而冻结视图的判定是：

```swift
isLinkedFrozenView = isLinkedNonSource && !isLinkedSecondCursorView
isLinkedNonSource   = cursorLinkEnabled && linkSync.cursorDate != nil && linkSync.sourceID != selfIndex
```

于是**联动态下只要已存在光标、且来源是别的格**，主格就会被判为「非来源」→ 冻结 → 单指拖动完全不生效。

## 决策

**主格（`isMainTile`，即悬浮按钮驱动的那一格）排除在冻结之外**：

```swift
isLinkedFrozenView = isLinkedNonSource && !isLinkedSecondCursorView && !isMainTile
```

理由：主格必须**始终**能像「手拖主图」那样驱动光标，并在拖动过程中自然接管为联动来源 ——
这与规格「多图联动时以该视图为驱动、等同手拖主图」以及「点击 B' 把来源交给主格」
（见 [[20260919-点击B'平移窗口一根]]）是同一套定位。

**其余非来源格保持冻结**：冻结机制本就是为了避免多个视图互相抢着居中而打架，这条不能被削弱。

## 副作用与取舍

主格与当前来源格之间变成「**最后触摸者接管**」：在主格上拖动会让它成为来源，原来那一格随即转为冻结。
这是自然且可预期的（既有注释里本来就写着「对称联动语义：任一视图只要正在被用户拖动光标即为来源端」）。

## 单图模式不受影响

`isMainTile` 在单图恒为 `true`，但 `isLinkedNonSource` 要求 `cursorLinkEnabled`（单图为 false），
故单图永远不会走到这条判断。
