# 点击 B' = （按需）清全部光标 → 窗口平移一根 → 在最右缘放光标（2026-09-19）

## 决策

点击新按钮的 B'（位移 ≤ `tapSlop`）时由**主格**执行三步，顺序固定：

1. **按需**清除屏幕上全部视图的所有光标；
2. 可见窗口朝**更新**方向平移 **1 根 K 线**（屏幕上 K 线整体左移、右缘进来一根更晚的）；
3. 把光标放在**平移后**的**最右侧可见 K 线**上，并发布联动光标。

果冻回弹照旧播放，与这三步同时发生。点击**不打开面板**（面板仍只由旧按钮打开）。

## 第 1 步为什么「按需」

若本视图**已是联动驱动来源**且**光标已在最右侧可见 K 线**上：

```swift
cursorLinkEnabled && linkSync.sourceID == selfIndex && selectedIndex == endIndex
```

当前状态**就已经是本次点击的终态**，整轮清除纯属多余。而且有可见副作用：清除会把 `crosshairY` 一并置 nil，
随后第 3 步又把它重置到主图中线 —— 用户看到的是「横线无端跳回中线」的闪烁。所以这一步要跳过。

## 清光标为什么必须同步，且不能由详情页换 token

第一版实现把清除挂在 `KlineDetailView` 的 `cursorClearToken` 上（与「退出联动」同一写法），**这是错的**：

- `cursorClearToken` 是 `@State`，各图靠 `.onChange(of:)` 响应，而 `onChange` **要到下一次渲染才生效**；
- 点击命令的 `.onReceive` 则是**发布时同步投递**的；
- 于是顺序变成「先放新光标 → 渲染时再按 token 清一遍」→ **刚放好的光标被自己擦掉**。

所以清除改为：每个 `KlineChartView` **同步订阅** `FloatingAccessoryCoordinator.$clearAllCursorsSeq`
自行清除（有意**不判** `isMainTile` —— 要清的就是所有格），并顺带清空共享的联动光标字段
（否则联动开启时其余格会按 `linkSync.cursorDate` 把光标再画回来）。「清本地光标」的代码与
`cursorClearToken` 广播、「边」开启两处收敛为同一个 `clearLocalCursors()`。

**重入问题不存在**：清光标的广播是在 `$windowNudge` 的投递里发出的，两者是**不同的 subject**，
不是同一个 publisher 的重入发送。

## 第 2、3 步的顺序与两个必须显式做的事

- **先移窗、后放光标**：终态才是「光标停在可见窗口最右侧那一根」，与既有「光标贴边推进」同一惯用法
  （`applyAccessoryCursorAdvance` 分支③ 推进窗口后会把光标重新锁回新边缘）。反过来先放再移，
  光标最后会落在右缘左边一根。
- **必须显式 `publishLinkCursor(index:)`**：放光标时要把 `cursorDragging` 置 true 才符合发布的守卫条件
  （「本地光标模式」），而这个标记**必须马上复位**（否则后续轻点会被 `onEnded` 的 `cursorDragging`
  分支吞掉、光标再也点不掉 —— 既有教训）；但 `selectedIndex` 的 `.onChange` 要到下次渲染才触发，
  那时标记已复位、发布会被守卫挡掉。所以在这一个同步块里**直接发布一次**，让联动各格自洽跟随。
- 到数据边界时窗口不平移，但**仍然放光标** —— 「最右缘有光标」与「窗口能不能再前进」是两件事。
