# K 线指标组合体系 + 指标缓存磁盘化管理

## Context

用户反馈启动卡顿后，提出两个配套需求（已通过 AskUserQuestion 确认关键决策）：

1. **指标组合体系**：K 线设置面板新增配置组——下拉菜单（第一项=「局部独立配置」=现存按周期记忆配置；其余 5 项=五套全局默认组合）+ 按钮（弹出全屏组合编辑页）。组合粒度=**仅启用集合**（主图启用集合+主图自定义+三副图选择），不含指标参数（参数保持全局）。下拉切换全局生效。
2. **指标缓存磁盘化 + 缓存管理**：指标缓存按 (组合, 标的, 周期) 持久化到 **sqlite**（用户指定；生成范围=**全市场** 3354 只）。个人中心新增「缓存管理」全屏 Web 页：显示 6 个组合各自缓存占用、多选清除、多选组合生成（全量=完整计算；预热=只算最新 N 根近似，N 可配置）。

关键现状（已核实）：指标配置 `mainIndicatorsByPeriod/subscriptByPeriod/activeCustomByPeriod` 为**纯内存态**（重启丢，仅 chartStyle/displaySettings 等落盘）；指标缓存 `ChartCacheStore` 内存 LRU 3 标的、`configFingerprint` 失效；组合编辑页入口在设置弹层内 → 必须走 **sheet 域**（WebFullscreenPageHost 会被 K 线详情页盖住）；缓存管理页入口在个人中心 → 走 **page 域**。

## 设计要点

### 数据模型（期1）
- 新 `Kline/Chart/ChartPreset.swift`：`ChartPreset`（Codable，id "p1"…"p5" 固定槽、name、mainIndicators: Set<String>、activeCustomID: UUID?、subSelections: [SubChartSelection]）。
- 新 `Kline/Chart/ChartPresetStore.swift`（单例）：`presets: [ChartPreset]` 固定 5 槽 + `activeMode: ChartConfigMode`（`.local | .preset(id)`）；UserDefaults JSON 持久化（`kline.chart.presets.v1` / `kline.chart.activeMode`）。
- **resolver 注入**（调用方零改动）：[ChartConfigStore.swift](file:///Volumes/home/repositories/Kline2/Kline/Chart/ChartConfigStore.swift) 的 `mainIndicators(for:)/subSelections(for:)/activeCustomIndicatorID(for:)` 先查 activeMode——preset 模式返回对应 preset（缺槽回退默认集合），local 走现 byPeriod；写路径（toggleMainIndicator/recordSubKinds/setActiveCustom）按模式分流：**preset 模式就地改写 preset**（生效中即编辑语义），local 不变。
- **局部配置补落盘**：三字典 didSet 序列化 UserDefaults（`kline.config.byPeriod.v1`），init 恢复——修复现状重启丢失。

### 指纹与缓存键（期1 + 期3）
- [IndicatorPipeline.swift](file:///Volumes/home/repositories/Kline2/Kline/Chart/IndicatorPipeline.swift) L1626 `currentConfigFingerprint(period:)` 前部拼接 `mode + presetId`（算法不动，resolver 返回值已隐含组合内容；preset 模式下编辑自动失效）。
- 期3：`ChartCacheStore.CacheKey` 增加 `comboKey` 维度；内存 LRU maxMetaCount 3→4，淘汰**不删磁盘**。

### 磁盘缓存（期3）
- 新 `Kline/Chart/IndicatorCacheDB.swift`：独立 `indicator_cache.db`，复制 [DatabaseManager.swift](file:///Volumes/home/repositories/Kline2/Kline/Data/DatabaseManager.swift) 的 SQLite3 串行队列模式（**不与行情主库混用**）。表：`cache(comboKey, meta_id, period, fingerprint, mode('full'|'warm'), bar_count, main_curves BLOB, sub_curves BLOB, coverage_end, bg_coverage_end, updated_at, last_bar_date INT, source_bar_count INT, PRIMARY KEY(comboKey, meta_id, period))`；IndicatorLine 数组 Codable→BLOB。
- 读路径：`entry(for:)` 未命中返回空 Entry + 异步查 sqlite 注水（fingerprint 匹配才注），注水后 @Published 信号触发重渲染；写回前校验 fingerprint 防与前台近似计算竞态。
- **数据联动失效（补缺口 / 清单标的自动更新）**：现状两场景均走「增量库热重载 → dataVersion 自增 → ChartCacheStore.clearAll()」（DatabaseManager L50/L72/L219），内存缓存全清成本为零，但磁盘缓存生成成本高**不能跟随全清**，改用**行级校验**：
  - `last_bar_date`（生成时该标的该周期末根日期）：补缺口/每日增量只追加尾部 → 读注水时对比主库最新日期，不一致才视为过期（其余行继续有效）；
  - `source_bar_count`（生成时源数据根数）：覆盖主库结构性合并改写（日期不变但历史被改写）的场景；
  - `fingerprint`：组合模式/指标配置变化失效（期1 已并入）。
  - 校验不过 → 忽略磁盘行走现有计算管线，磁盘行**保留**并在管理页标记「过期待更新」；不自动删除。
  - **清单标的自动更新**：删除标的 → 孤儿行在 stats/clear 时按当前 metaList 差集回收；新增标的 → 无行，由生成动作补。
  - 管理页 stats 报 `staleCount` +「刷新过期」便捷动作（generate {onlyStale: true}，只重跑过期标的）。

## 风险与量级

- **计算量**：全量 3354 只 ≈ 28~56 分钟/组合；预热 N=80(+120 buffer) ≈ 6~17 分钟/组合。默认仅日线+预热 N=80；全量建议手动低峰跑。批次让路前台计算。
- **磁盘体积**：单组合全市场日线 ≈ 100~270MB，6 组合上限 ≈ 1.6GB；管理页明示占用。
- **一致性**：指纹+dataVersion 双闸失效；注水异步与前台写回竞态靠写回前 fingerprint 校验。
- **隔离**：sqlite IO 全走 nonisolated 串行队列（SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor，纯函数标 nonisolated）。
