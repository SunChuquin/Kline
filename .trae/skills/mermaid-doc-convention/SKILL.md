# Mermaid 配图规范

文档的主体是 Markdown 正文，Mermaid 图只是辅助理解的插图。图不能替代文字，也不能指望读者靠一张大图理解全部机制。

## 何时使用

需要把机制、流程、架构、状态流转整理成文档，并在其中插入 Mermaid 图时。

写模块知识文档时由 `module-knowledge-digest` 一并加载：**图由该技能的「何时需要新加一张图」判定，格式由本技能约束。**

## 核心原则

1. **正文优先**：先用文字把机制讲清楚，再用图做补充。图是"这句话的可视化注解"，不是"这段话的替代品"。
2. **一图一事**：一张图只表达一个主题。不同阶段、不同层级、不同关注点的内容，拆成多张图，图与图之间用正文过渡。
3. **节点受控**：一张图无论横向还是纵向，要求其节点链长度 ≤5，而一张图最多 5 条互不连线的链
4. **跨图连线能省则省**：如果一张图里出现大量跨 subgraph 的长箭头，说明该拆图了。
5. **图外必有说明**：每张图前用一句话说明"这张图讲什么、从哪看起"，图后必须补"图里没画出来的部分"。禁止只丢一张图让读者自己悟。

## 图表类型选择

- **流程 / 时序**：用 `flowchart LR`（横向）或 `flowchart TB`（纵向）。阶段多、有先后顺序时优先横向。
- **模块并列 / 结构**：用 `flowchart` + `subgraph`，每个 subgraph 表达同一层级的并列模块。
- **状态流转**：用 `stateDiagram-v2`。
- **时序交互**：用 `sequenceDiagram`。
- **不要用** **`flowchart`** **硬画所有东西**。层级关系用文字列表往往比图更清楚。

## 节点写法

- 节点标签简短，必要时用 `<br/>` 换行，但不超过两行。
- 详细字段、SQL、函数签名不写进节点，放到正文的代码块或列表里。
- 配色 `style` 只用于区分模块归属，不要为了好看堆一堆颜色。颜色种类控制在 3\~4 种。
- 注释 `%%` 用于分隔区块，不要写大段说明。

## 拆分示例

**不推荐**：一张图里同时画"数据生成 + 数据库加载 + 查询路径"，20+ 节点，跨 subgraph 连线多条。

**推荐**：拆成三张图，每张 5\~10 节点，正文按顺序写：

1. 数据生成（离线工具产出种子库）
2. App 启动与数据库加载（种子库复制到 Documents、打开、加载 meta）
3. 查询路径（页面触发、经 dbQueue 串行访问）

三张图之间用一两句正文过渡，读者先读文字再看图，理解成本远低于一张大图。

## 每张图固定三件套

1. **图前一行**：这张图讲什么、从哪个节点读起（例："从 `[ * ]` 起读；每个状态描述行里是该态的外观取值"）
2. **图本体**
3. **图后「图里没画出来的部分」**：列 1~3 条。
   凡是为图清晰而牺牲的信息都放这里 —— 叠乘关系、稳定态 vs 过渡态、与正文重复的判定条件。
   **不写这节，图就会被当成完整真相**，这是最容易误导未来读者的地方。

## 语法陷阱（不写会渲染失败或画出白图）

- `stateDiagram-v2` 的**状态 id 必须是 ASCII**：中文直接当 id 在部分渲染环境会失败。
  正确写法是「ASCII id + 描述行」，迁移里引用 id：

  ```
  stateDiagram-v2
      s0 : 常态 · opacity 100%
      s1 : 摁住/拖动 · opacity 50% · 直径 ×1.15
      [*] --> s0: onAppear
      s0 --> s1: onChanged 首次
  ```

- `flowchart` 的**节点 id 用 ASCII，中文放 `[]` 标签里**：`A[ContentView 顶层 overlay]`。
- 连线/迁移标签里可以放中文，但避开 `[` `]` `(` `)` 等会与语法冲突的字符；
  需要时改用全角「（）」或 `·` 分隔。

## 什么时候才需要新加一张图

| 触发条件 | 画什么 | 例 |
| --- | --- | --- |
| 涉及 **≥2 个模块**的判定或装配点 | 结构 / 范围流程图 | 按钮显示范围由 `selectedTab` 门控 |
| 出现 **≥3 个状态或 ≥3 步流程** | 状态图 / 时序图 | 触摸四态与迁移 |
| 只是"类 A 调 类 B"的一句调用关系 | **不画**，正文写一行文字即可 | 画了是噪音 |

单篇文档配图 ≤2 张（结构一张、机制一张）；再多说明该拆篇了。

## 自检清单

产出文档前逐条检查：

- [ ] 每张图是否只讲一件事？
- [ ] 单张图节点数是否 ≤ 15？
- [ ] 是否每张图前都有"这张图讲什么、从哪读起"的一句话？
- [ ] 是否每张图后都有「图里没画出来的部分」？
- [ ] 状态 id / 节点 id 是否都是 **ASCII**（中文只在描述行或 `[]` 标签里）？
- [ ] 图里是否塞了本该放正文的细节（字段、SQL、长函数签名）？
- [ ] 是否能用文字列表替代的，却硬画成了图？
- [ ] 跨 subgraph 连线是否过多，是否该拆图？
- [ ] 配色是否只为区分模块，而非装饰？

任何一条不满足，先改文档再交。
